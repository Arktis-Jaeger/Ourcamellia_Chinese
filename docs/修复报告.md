## C. 缺陷修复

### 缺陷 A：Observatory 模式"提示可见但无法输入"

- **根因**：主循环原用 `input.available() > 0` 判断是否有按键输入；但 JLine 的
  `NonBlockingInputStream` 并未重写 `available()`（基类恒返回 0），因此该条件
  永远不成立，读取循环从不执行——任何输入都不会被读取。
- **修改文件**：
  - `client/.../ObservatoryUi.java`：新增 `readInputByte(InputStream, long)`——
    对 JLine 非阻塞流调用 `nb.read(remaining)`（`-1`/`-2` 表示当前无数据，短暂
    休眠后继续），非 JLine 流退回 `available()` 路径；主循环改用它读取按键。
- **方案要点**：完全在既有 JLine 非阻塞输入框架内解决（未换终端库、未禁用任何
  终端事件）。

### 缺陷 B：拖动窗口 / 极端尺寸导致进程崩溃

- **根因**：`LineEditor.render` 对 `terminalWidth <= 0`（长标题 + 窄窗口把可用宽度
  算成 0 或负数）时对行文本执行 `substring()`，抛出
  `StringIndexOutOfBoundsException`；渲染异常未被捕获，直接杀死进程。
- **修改文件**：
  - `client/.../LineEditor.java`：可用宽度钳制 `Math.max(1, terminalWidth)`；
    `keep` 钳制 `Math.max(1, Math.min(长度, width-1))`；`inputDirty` 输入行只做
    局部重绘。
  - `client/.../ObservatoryUi.java`：`width`/`height` 改为 `volatile`（信号线程
    写入）；WINCH 处理器 try/catch 读取尺寸失败时回退旧值；`safeRender()` 捕获
    `RuntimeException` 并输出诊断（连续 `MAX_RENDER_FAILURES = 5` 次失败才请求
    退出——不静默吞错，也不在单次渲染异常时立即杀进程）。
- **方案要点**：通过钳制与兜底诊断解决，未依赖关闭刷新/捕获全部异常规避。

### 验证（真实终端，PTY）

- 在真实 PTY 中启动 `--mode observatory`：
  - 键入 `你好，世界` 实时回显到屏幕（缺陷 A 已修复）✓
  - 60 次密集 `SIGWINCH`（rows 2..47 × cols 4..123 极端组合）+ 极端窄窗口
    （5×12）持续键入，进程全程存活（缺陷 B 已修复）✓
  - `${quit}` 正常退出，退出码 0 ✓

### D.6 遗留问题与说明（如实）

1. Observatory 主菜单/无会话视图不会在屏幕上显示命令输出（`${help}`、`${info}`、
   错误行等）——这是**原设计**：`conversationView` 仅在打开会话时渲染 transcript
   （L3），菜单视图（L1）与会话列表（L2）不渲染。在 Old 模式或进入会话后文本照常
   显示。本版未改变该渲染路由。
2. 同原因的说明：旧验证脚本 `verify_fixed.py` 中"菜单视图回车无提示""help 输出"
   两项检查为脚本预期与上述设计不符所致，非产品缺陷；其余全部检查项（输入回显、
   退格、光标移动插入、中文显示、50 次 WINCH、极端尺寸、窄窗口、`${quit}` rc=0）
   均通过。
3. Observatory 渲染中 CJK 文本宽度为近似计算（原项目已知限制，未在本版改动）。
4. BOT API HTTP 适配器的 JSON 响应键值与错误串（`ok/sent/pending/missing token`…）
   按 API 契约保留英文。
5. `mvn package` 若要真正执行 `ObservatoryPtyIT`，需在支持 PTY 的 POSIX 主机上以
   可用的 `/dev/pty` 运行（沙箱/受限 CI 中自动跳过，不阻塞构建）。
