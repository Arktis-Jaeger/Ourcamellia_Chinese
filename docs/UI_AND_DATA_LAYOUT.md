# Terminal UI 与便携式数据目录

本文说明本次重构后的终端界面规则、键盘操作与聊天记录目录。业务协议、认证、
好友/群组规则、通知语义与加密机制未作改变。

## 1. 展示模式

| 配置 | 值 | 说明 |
|---|---|---|
| `terminal.mode` | `OBSERVATORY`（默认） | 固定布局终端界面 |
| `terminal.mode` | `OLD` | 逐行输入/输出，适合脚本与管道 |

命令行 `--mode observatory|old` 优先于配置。`auto` 仅作为旧值兼容，按
Observatory 处理并打印提示；程序不会根据终端能力自动切换。

旧版顶层 `mode` 字段仍然兼容：当 `terminal.mode` 保持默认值而旧字段为
`old`/`observatory` 时，沿用旧字段。若要从旧配置切换到 Observatory，请删除
旧的 `mode` 字段或使用 `--mode observatory`。

## 2. 键盘

| 按键 | 行为 |
|---|---|
| ↑ / ↓ | 菜单、列表移动焦点；帮助页滚动 |
| Enter | 确认；表单下一字段/提交；命令栏提交；消息输入换行或发送 |
| Shift+Enter | 与 Enter 相反（由 `terminal.shiftEnterToSend` 决定） |
| Tab / Shift+Tab | 表单切换字段（含命令栏）；聊天中切换消息输入与命令栏 |
| Esc | 返回上一级；命令栏有内容时先清空 |
| PgUp / PgDn | 滚动消息或帮助 |
| Ctrl+S | 发送消息（终端无法区分 Shift+Enter 时的替代方式） |
| Ctrl+C | 清空当前输入行 |
| I | 会话列表中打开通知（命令栏为空时） |

`terminal.shiftEnterToSend`：

| 值 | Enter | Shift+Enter |
|---|---|---|
| `true`（默认） | 换行 | 发送 |
| `false` | 发送 | 换行 |

该规则只用于聊天消息输入；菜单 Enter 永远确认，命令栏 Enter 永远提交。

如果终端把 Shift+Enter 与 Enter 发送成同一个字节，程序无法凭字节区分二者；
此时请使用 Ctrl+S 发送。界面提示与 `${help}` 会明确说明，不会假装组合键已生效。

## 3. 页面结构

- 最上方/最下方：由 `=` 组成、占满当前终端宽度的横线；
- 中间区域：由 `-` 组成、同样占满宽度的横线；
- 页面有上下文标题（通知、`服务器@名称`、`本地@IP`、群名；私聊无独立标题）；
- 菜单/列表使用 `>` 表示焦点；
- 所有可交互页面都有命令输入栏（全屏帮助页为唯一例外，返回后恢复原页面）；
- 聊天页把“消息”“消息输入”“命令”三个区域分开；
- 窗口尺寸变化时横线与布局按新宽度重算。

## 4. 聊天记录目录

默认数据目录为程序目录下的 `data/`（打包运行时是发行目录，开发运行时是仓库根）。
可用 `--data-dir` 或配置 `dataDir` 覆盖。程序拒绝把数据目录放在编译输出
`target/` 或学习材料 `Study/` 中；目录不可写时明确报错，不会静默改写到用户主目录。

```
data/
├── chats/
│   ├── local/
│   │   └── <本地会话标识>/conversation.json
│   └── servers/
│       └── <IP>/
│           └── <服务器标识>/
│               ├── server.json
│               └── conversations/
│                   ├── priv-<...>.json
│                   ├── group-<...>.json
│                   └── channel.json
├── state.json
└── logs/
```

- 服务器标识由 TLS 证书指纹派生（无指纹时退化为名称哈希），因此服务器改名不会
  改变目录；同一 IP 下可保存多个服务器子目录。
- 所有名称/ID 在拼接路径前经过安全化处理，防止路径穿越与名称冲突。
- 文件编码 UTF-8；使用原子替换写入；损坏文件隔离为 `*.corrupt-*`，不静默覆盖。
- 旧版 `<data>/history/*.json` 仍可读取；只有下一次保存才写入新位置，旧文件保留。

### 手工迁移（服务器 IP 变化）

1. 找到 `data/chats/servers/<旧IP>/`；
2. 找到对应服务器子目录；
3. 把**整个服务器子目录**移动到 `data/chats/servers/<新IP>/`；
4. 如有需要，修改 `server.json` 的 `address`；
5. 重新连接，程序按服务器标识识别原记录。

程序不自动移动、合并没有验证过的历史；迁移一个服务器不会影响同 IP 下的其他服务器。
